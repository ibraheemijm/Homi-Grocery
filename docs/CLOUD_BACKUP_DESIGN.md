# تصميم النسخ الاحتياطي السحابي

الحالة: تصميم مقترح فقط — لم يُفعّل الاتصال السحابي ولم تُرفع بيانات متجر.

## المتطلبات المعتمدة

- النسخ الاحتياطي المحلي والسحابي معًا.
- الاحتفاظ بالنسخ السحابية لمدة 90 يومًا، ثم حذفها تلقائيًا والتحقق من أن سياسة الحذف قابلة للاختبار.
- إبقاء النسخ المحلية عاملة عند انقطاع الإنترنت أو تعطل المزوّد.
- عدم رفع بيانات فعلية قبل اعتماد المزوّد وإعداد التوثيق وتفعيل الميزة صراحة.
- لا تغيير على مخطط SQLite أو عمليات البيع والمرتجعات والخزينة من أجل هذه الميزة.

## تصميم مقترح مستقل عن المزوّد

1. إنشاء نسخة SQLite متسقة باستخدام المسار المحلي الحالي.
2. التحقق من سلامة النسخة ورقم المخطط قبل تشفيرها.
3. تشفير الملف كاملًا محليًا قبل مغادرته الجهاز باستخدام تشفير موثّق (AEAD)، ومفتاح عشوائي لكل نسخة؛ لا تُضمّن مفاتيح التشفير أو رموز الوصول داخل المستودع أو التطبيق.
4. رفع الملف المشفر عبر HTTPS إلى مساحة تخزين خاصة غير عامة. تُحفظ بيانات الفهرسة الدنيا اللازمة للتعرّف على النسخة (معرّف عشوائي، وقت الإنشاء، إصدار التنسيق، nonce/tag، وحجم الملف)، ولا تُرسل أسماء الأصناف أو بيانات الفواتير في أسماء الكائنات.
5. التحقق من اكتمال الرفع عبر الحجم وبصمة المحتوى، ثم تسجيل حالة النجاح محليًا. الفشل لا يحذف النسخة المحلية.
6. للاستعادة: تنزيل الملف المشفر، والتحقق من سلامة النقل، ثم فك التشفير محليًا، والتحقق من SQLite، ثم استخدام مسار الاستعادة والتراجع الحالي.
7. الاحتفاظ السحابي: سياسة حذف بعد 90 يومًا بتوقيت UTC، مع تنظيف مجدول آمن قابل للاختبار، ومعالجة حالات انقطاع الشبكة والفشل الجزئي وإعادة المحاولة دون إنشاء نسخ مكررة بلا نهاية.
8. واجهة الإعدادات تعرض المزوّد وحالة الاتصال وآخر رفع ناجح وآخر خطأ، وتوفر أزرار رفع/استعادة يدوية في البداية. لا تفعيل افتراضي ولا حذف للنسخة المحلية بعد الرفع.

## حواجز الأمان والموثوقية

- المصادقة والتفويض على مستوى المستخدم/المتجر؛ لا حاوية عامة ولا مفاتيح سرية ضمن Git.
- تشفير قبل الرفع، مع توثيق كيفية حفظ مفتاح التشفير واستعادته بعد تغيير الجهاز. فقدان المفتاح يعني فقدان إمكانية فك النسخ؛ لا يبدأ التنفيذ قبل اعتماد خطة مفاتيح قابلة للاسترداد.
- حدود لحجم الملف، ووقت انتهاء للطلبات، وإلغاء آمن، وإعادة محاولات بتأخير متزايد.
- منع رفع قاعدة البيانات الحية مباشرة؛ ارفع فقط لقطة متسقة اجتازت الفحص.
- عدم اعتبار الرفع ناجحًا حتى يكتمل تحقق الحجم والبصمة.
- لا يعتمد نجاح CI وحده على التوافق مع حساب مزوّد فعلي؛ يلزم اختبار تكامل دون بيانات حقيقية ثم اختبار قبول صريح.

## قرار المزوّد المطلوب قبل التنفيذ

لم يُعتمد مزوّد بعد. الخيارات التي تستحق المقارنة:
- **Cloudflare R2 عبر Worker خاص**: مناسب لتخزين كائنات مشفرة، لكن يتطلب إنشاء/إعداد bucket خاص وواجهة Worker وتوثيق المستخدم وصلاحيات وصول منفصلة. لا نفترض أن حساب Cloudflare المتصل بمشروع آخر هو الحساب المناسب لهذا التطبيق.
- **Google Drive**: مألوف للمستخدم، لكنه يتطلب تدفق OAuth وصلاحيات ملفات دقيقة وإدارة تجديد الرموز.
- **مزوّد S3-compatible آخر**: ممكن، لكن يتطلب إدارة endpoint ومفاتيح وصول آمنة.

قبل التنفيذ، يجب اعتماد المزوّد وطريقة ربط النسخة بحساب المتجر، وكيفية استرداد مفتاح التشفير، وهل النسخ السحابية يدوية أم تلقائية بعد موافقة المستخدم. لا تضاف تبعيات ولا إعدادات أسرار ولا عمليات رفع فعلية قبل حسم هذه القرارات.
