# تفعيل Homi Grocery — المسار المعتمد بالملفات

## القرار الحالي

اعتبارًا من 25 نوفمبر 2026، يعتمد الإصدار الحالي التفعيل وتجديد الاشتراك عبر الملفات فقط. لا يرسل التطبيق طلب تفعيل مباشرًا إلى المنصة، ولا يسجل التجربة أو يجدد تصريح Offline عبر الإنترنت.

## رحلة العميل

1. يدخل المستخدم اسم العميل/المتجر ورقم الهاتف والخطة المطلوبة داخل شاشة التفعيل.
2. ينشئ التطبيق ملف طلب `.hreq` موقعًا بمفتاح الجهاز الخاص المحفوظ في التخزين الآمن.
3. يشارك العميل الملف مع إدارة Homi عبر WhatsApp أو وسيلة التواصل المتفق عليها.
4. ترفع الإدارة الملف من لوحة Homi Admin المحمية. تتحقق المنصة من بنية الملف وتوقيع Ed25519 وبصمة الجهاز، ثم تسجل الطلب.
5. تراجع الإدارة بيانات العميل والخطة وتؤكد استلام الدفع يدويًا قبل إصدار الترخيص المدفوع.
6. تصدر المنصة ملف `.hlic` موقعًا بمفتاح Ed25519 الخاص بالخادم.
7. ترسل الإدارة الملف إلى العميل.
8. يستورد العميل ملف `.hlic` داخل التطبيق. يتحقق التطبيق محليًا من التوقيع والمنتج والجهاز والتواريخ وسياسة الوصول قبل حفظ الترخيص.

## حدود الاتصال

- لا يحتاج إنشاء `.hreq` أو استيراد `.hlic` أو التحقق من التوقيع إلى اتصال بالإنترنت.
- اتصال الإنترنت أو WhatsApp مطلوب فقط لتبادل الملفات مع إدارة Homi، وليس لتفعيل التطبيق.
- التجربة المجانية المحلية تبدأ عند أول دخول فعلي للمدير وتستمر 14 يومًا وفق السجل المحلي، دون تسجيل مركزي.
- تجديد الترخيص يتم بإصدار `.hlic` جديد واستيراده.
- لا يُسمح بتفعيل ترخيص مدفوع أو تمديده قبل تأكيد الإدارة استلام المبلغ.
- مسارات API المباشرة والتسجيل المركزي للتجربة وتجديد Offline Grants تبقى مؤجلة للمستقبل، ولا تستدعيها واجهة التطبيق الحالية.

## صيغة HREQ v1

الغلاف JSON:

```json
{
  "format": "HOMI_ACTIVATION_REQUEST",
  "format_version": 1,
  "payload": "BASE64URL_UTF8_JSON_PAYLOAD",
  "signature": "BASE64URL_ED25519_SIGNATURE"
}
```

التوقيع يغطي النص التالي حرفيًا:

```
HOMI_HREQ_V1
{SHA256_HEX_OF_EXACT_PAYLOAD_BYTES}
```

تتضمن الحمولة معرف الطلب والجهاز وبيانات العميل والخطة والمنصة والمعمارية والمفتاح العام وبصمته وإصدار التطبيق. لا تتضمن بريدًا إلكترونيًا أو كلمة مرور أو المفتاح الخاص أو بيانات المتجر التجارية.

## صيغة HLIC v1

الملف JSON UTF-8 بامتداد `.hlic`. يغطي توقيع Ed25519 بايتات payload الأصلية كما هي. يتحقق التطبيق من:
- معرف المنتج `homi-grocery`.
- مفتاح التوقيع ضمن مفاتيح الثقة المضمنة.
- توقيع Ed25519.
- بصمة المفتاح العام للجهاز الحالي.
- حالة الترخيص والتواريخ وسياسة الوصول.

لا يستبدل التطبيق ترخيصًا صالحًا ولا يمسح طلبًا أو سجلًا سابقًا إلا بعد نجاح جميع الفحوص. ولا يؤدي الاستيراد أو رفض الملف إلى حذف أي بيانات من قاعدة بيانات المتجر.

## إعدادات البناء

- `HOMI_LICENSE_TRUSTED_PUBLIC_KEYS_B64`: مفاتيح التحقق العامة فقط.
- `HOMI_PLATFORM_ROOT_KEY_ID`: معرف مفتاح الجذر الذي يوقع keyset.
- `HOMI_PLATFORM_ROOT_PUBLIC_KEY`: المفتاح العام للجذر بصيغة Base64.
- `HOMI_APP_VERSION` و`HOMI_BUILD_NUMBER`: بيانات الإصدار داخل ملف الطلب.

لا تضع مفتاح توقيع خاصًا أو أسرار المنصة في تطبيق Flutter أو GitHub.

## تحديثات التطبيق (OTA)

تحديثات التطبيق منفصلة عن التفعيل والاشتراك، ويمكن الإبقاء على فحصها وإدارتها عبر الإنترنت وفق مفاتيح الثقة وتوقيع manifest. لا يعني قرار التفعيل بالملفات إيقاف OTA.

- يتحقق التطبيق من keyset وmanifest والحجم وSHA-256 قبل إتاحة التنزيل والتثبيت.
- Android يستخدم مثبت النظام الرسمي بعد موافقة المستخدم.
- Windows يستخدم HomiUpdateLauncher مع UAC والتحقق والاسترجاع عند الفشل.
- لا يوجد تثبيت صامت، ولا يغير التحديث قاعدة بيانات المتجر أو مجلد بيانات Homi.
